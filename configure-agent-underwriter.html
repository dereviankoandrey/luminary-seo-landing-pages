Layer 1: System Prompt Architecture

The system prompt is your first and most important configuration. It must enforce deterministic thinking patterns, not creative interpretation.

Base Underwriting Agent Prompt (Qwen / Llama-3 Compatible)

You are a real estate underwriting analyst operating with deterministic logic only. RULES: 1. NEVER fabricate data, comparable sales, or market statistics 2. ALWAYS show your calculation steps — every number must be auditable 3. When input data is missing, state "DATA_GAP: [field]" and do not guess 4. Apply conservative assumptions by default (lower rent estimates, higher vacancy) 5. Flag any assumption that significantly impacts the conclusion OUTPUT FORMAT: - Deal Summary: [property type, location, price] - Income Analysis: [sources, gross income, vacancy adjustment] - Expense Analysis: [TAX, INSURANCE, MAINTENANCE, MANAGEMENT, VACANCY] - Cash Flow: NOI = Gross Income - Operating Expenses - Metrics: Cap Rate = NOI / Purchase Price, Cash-on-Cash = Annual CF / Total Cash Invested - Risk Flags: [list any concerns] - Confidence Level: HIGH/MEDIUM/LOW based on data completeness VERIFICATION CHECK: Before presenting final numbers, verify: - Cap rate is within ±2% of market median for the area - Debt service coverage ratio > 1.15x (or state if below) - Cash-on-cash return calculation uses actual cash invested (not asking price)
💡 Pro Tip: For Qwen models, add "You are an expert real estate analyst with 20+ years of experience in both US and Australian markets" to leverage the model's instruction-following strength. For Llama-3, emphasize the rule-based structure more heavily.

Mistral Variant (More Concise)

You are a deterministic underwriting engine. Rules override creativity. - No fabricated data. Show all calculations. Flag gaps. - Conservative defaults: 5% vacancy, 8% maintenance of NOI, 10% management fee if self-managed, 2% capex reserve. - Output: Deal Summary → Income → Expenses → Cash Flow → Metrics (Cap Rate, CoC, DSCR) → Risk Flags → Confidence If any input is missing, output "DATA_GAP: [field]" instead of guessing.

Layer 2: RAG Pipeline for Market Data

The agent needs access to current market data without hallucination. A Retrieval-Augmented Generation (RAG) pipeline provides structured, verifiable inputs.

Evaluation Scorecard (Per Deal)

Deterministic Score = (Data Completeness × 0.3) + (Formula Transparency × 0.3) + (Market Alignment × 0.2) + (Risk Flagging × 0.2) Where: - Data Completeness: % of required fields provided vs missing - Formula Transparency: Can every output number be traced to an input? - Market Alignment: Are assumptions within published market ranges? - Risk Flagging: Did the agent flag all applicable risk conditions?
🎯 Key Insight: Black-box AI models score 0 on Formula Transparency by design — you can't trace their outputs. Our deterministic approach scores near-perfect here, which is the single biggest differentiator for investors who need defensible analysis.

Common Pitfalls & Fixes

Pitfall 1: Agent "Helpfully" Fills Data Gaps

Symptom: Agent invents cap rates or comparable rents when data is missing.

Fix: Add explicit rule to system prompt: If required input is missing, output "DATA_GAP: [field]" and STOP. Do not estimate or infer values.

Pitfall 2: Temperature Too High for Underwriting

Symptom: Same deal produces different numbers on repeated runs.

Fix: Set temperature ≤ 0.15 for any underwriting agent. For rule-checking agents (risk auditor), use ≤ 0.05.

Pitfall 3: No Output Schema Enforcement

Symptom: Agent outputs free-form analysis that's hard to parse or compare across deals.

Fix: Define strict JSON output schema and enforce it in the system prompt. Require all numeric fields as separate values, not embedded text.

Pitfall 4: Single Model for Everything

Symptom: One model trying to extract data, calculate numbers, check risks, and write reports — does none well.

Fix: Use specialized models per role. Smaller/faster for extraction (Mistral-7B), stronger reasoning for underwriting (Qwen2.5-14B), rule-focused for auditing (Llama-3-8B).
